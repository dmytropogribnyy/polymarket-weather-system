# Методология

Документ описывает, как система превращает метеорологические данные в
конкретную ставку с конкретным размером, **в том виде, в каком это работает
сейчас**. Единственный источник истины — `src/wx_daily.py`; HTML-скринеры
повторяют ту же математику на JavaScript, и это повторение проверяется тестом
паритета (`tests/test_parity.py`), а не обещанием.

> **Что изменилось после ревизии v2 (2026-08-02) и закрытия блокеров.**
> Разделы про *Historical Forecast* как источник калибровки, про одну общую
> поправку станции, про формулу `σ = 0.6 + 0.15·lead` и про стресс «сдвиг на
> ±std» описывали прежнюю версию и **удалены из описания текущей системы** —
> они перечислены в разделе 17 как исторические. Ниже описан только код,
> который выполняется сегодня.

## 1. Источники данных

| Что | Откуда | Зачем |
|---|---|---|
| Ансамблевый прогноз | Open-Meteo Ensemble API, модели `ecmwf_ifs025`, `gfs025`, `icon_seamless`, `gem_global` | ~143 члена ансамбля, почасовая температура |
| Прогноз прошлых суток | Open-Meteo **Previous Runs API**, `temperature_2m_previous_day1` и `previous_day2` | прогноз, каким он был за 24 и за 48 часов до дня — основа lead-matched калибровки |
| Исторический разброс ансамбля | Open-Meteo Ensemble API, `past_days=10` | средний разброс ансамбля в окне калибровки (`spread2`) |
| Факт по станции | aviationweather.gov METAR, окно 336 часов | что станция реально намерила |
| Рынки | Polymarket Gamma API (`events?slug=`), CLOB (`book?token_id=`, `markets/{condition_id}`) | цены, бакеты, стаканы, **торговые параметры рынка** |
| Позиции | Polymarket data-api `positions`, `activity` | что уже куплено и сколько уже потрачено |
| Землетрясения | USGS FDSN `count` и `query` | базовая интенсивность и текущий счёт |
| Крипта | Deribit `get_book_summary_by_currency` | подразумеваемая волатильность опционов |

Слаг Polymarket: `highest-temperature-in-{city}-on-{month}-{day}-{year}`, для
ночных минимумов префикс `lowest`. Из слага же берётся **дата погоды** —
именно она, а не UTC-дата сделки, служит ключом бюджета (раздел 11).

## 2. Контракт резолюции (fail-closed)

Станция берётся не «по городу», а из правил КОНКРЕТНОГО рынка. Разбор правил
(`parse_resolution`) вытаскивает три вещи: **источник** (Weather Underground /
NOAA), **станцию** (четырёхбуквенный код, сверяемый со списком станций
калибровки) и **единицы** (°C / °F). `check_resolution` не ставит, если правила:

* пустые или не разбираются;
* без распознанного источника, либо источников больше одного;
* без распознанной станции, либо известных станций больше одной;
* со станцией, отличной от той, на которой калиброваны наши поправки;
* с единицами, отличными от тех, в которых считает модель;
* **изменились** с прошлого наблюдения этого же рынка в прогоне (сверяется
  отпечаток текста правил, `resolution_fingerprint`).

Любой из этих случаев — NO BET, а не «предупреждение в карточке». Отказы
попадают в отчёт полем `resolution_checks`.

Реальные расхождения, которые это ловит: Шанхай резолвится по Пудуну (ZSPD),
Москва — по Внуково (UUWW), Сан-Франциско — по SFO с океанским бризом. Толпа
смотрит «погоду в городе» из телефона; на этом расхождении система и живёт.

## 3. Торговые параметры конкретного рынка

Комиссии, тик и минимальный ордер **не константы проекта**. Они читаются из
полей Gamma, а при их нехватке добираются из CLOB по `conditionId`
(`market_params`, `event_params`). Правила жёсткие:

* параметры обязаны быть у КАЖДОГО бакета события; нет хотя бы у одного — NO BET;
* значения вне санитарных границ (ставка > 20%, тик > 0.10, минимальный ордер
  > $100) считаются битыми данными — NO BET;
* ставка комиссии больше единицы трактуется как базисные пункты;
* при расхождении между бакетами берётся ХУДШИЙ вариант.

Полная цена входа: `allin(p) = p + rate·p·(1−p)`, где `rate` — ставка ЭТОГО
рынка. Погода, землетрясения и крипта используют свои параметры; общей
захардкоженной константы больше нет. Отказы — в поле `param_checks`.

## 4. Калибровка станции: lead-matched, по семействам

```
для каждого семейства f ∈ {ec, gf, ic, gm} и каждого горизонта lead ∈ {1, 2}:
    модельный максимум = max по часам прогноза семейства f,
                         выпущенного за lead суток до дня (Previous Runs)
    факт               = max по METAR этого дня (в местном времени станции)
    diff               = факт − модель
    bias_f = среднее diff, std_f = СКО diff, se_f = std_f / sqrt(n)
```

Ключевое: **у каждого семейства своя поправка и свой горизонт**. Урок Мюнхена
(2 августа): ECMWF требовал +2.3°, ICON +0.3°, а прибавлялось +2.5° всем.
Суточная калибровка не даёт права торговать двухсуточный прогноз, поэтому тир
считается **отдельно для каждого lead** (`tier_of`, `cal_tier`), и горизонт без
данных получает тир C.

Отсечка: сегодняшний день учитывается только после 19:00 местного времени
(для ночных минимумов — только вчерашний и раньше).

| Тир | Условие (на СВОЙ горизонт) | Следствие |
|---|---|---|
| A | n ≥ 6, max std ≤ 0.9, \|bias\| ≤ 4 | полное доверие |
| B | n ≥ 4, max std ≤ 1.5, \|bias\| ≤ 4 | полное доверие |
| C | всё остальное, а также отсутствие данных на этот горизонт | уверенность режется до 2/5, торговать нельзя |

Пример: у Лос-Анджелеса (KLAX) поправка ECMWF −7.8°C — это не поправка, а
признак другой точки резолюции.

## 5. Вероятность бакета

```
для семейства f:
    τ_f² = max(0.36, std_f² − spread2_f)
    для каждого члена ансамбля x семейства f:
        xc = x + bias_f
        p_член = Φ((hi − xc)/τ_f) − Φ((lo − xc)/τ_f)
    p_f = среднее по членам семейства
p = среднее по семействам (равный вес каждому семейству)
```

`[lo, hi]` — границы бакета, расширенные на ±0.5 градуса (бакет «31°C» означает
интервал [30.5, 31.5)). Для рынков в Фаренгейтах границы конвертируются в
Цельсий: ансамбль отдаёт градусы Цельсия.

Смысл `τ`: `std_f` измеряет ПОЛНУЮ ошибку прогноза — в ней уже сидит разброс
ансамбля. Вычитается **средний исторический разброс ансамбля того же семейства
в окне калибровки** (`spread2`, функция `hist_spread2`). Вычитать разброс
СЕГОДНЯШНЕГО прогноза нельзя: широкий сегодняшний ансамбль механически сжимал
бы ядро — ровно наоборот здравому смыслу. Нет исторического разброса —
не вычитается ничего (ядро шире, то есть консервативнее). Пол 0.36 (τ ≥ 0.6°)
не даёт ядру схлопнуться. Проверяется тестами
`tests/test_model_safety.py::TestResidualVariance`.

Семейство участвует, только если у него не меньше 8 членов ансамбля.

## 6. Усадка к рынку (лог-пул)

Своя вероятность смешивается с ценой рынка нормализованным лог-пулом:

```
p_итог ∝ p_модели^λ · q_рынка^(1−λ),   λ = 0.25 (фаза валидации)
```

Жёсткое условие: пул считается **только по полному взаимоисключающему набору
исходов** — от «X или ниже» до «Y или выше», без дыр и наложений
(`coverage_ok`). Если хоть один бакет не распознан или нет модельной
вероятности, событие целиком уходит в `pool_checks` и не торгуется.
Нормировать неполный поднабор к единице — значит выдумать вероятность;
`log_pool` этого не делает.

## 7. Устойчивость и согласие моделей

Та же вероятность считается ещё дважды со сдвигом поправки на **±SE среднего
своего семейства** (не на std — std это разброс ошибки, а не неопределённость
её среднего):

```
pLo = P(бакет | bias_f − se_f)      pHi = P(бакет | bias_f + se_f)
```

Сигнал устойчив (`robust`), если преимущество сохраняется в обоих сценариях.
Отдельно смотрится согласие семейств: одно семейство около нуля там, где
остальные дают много — флаг риска, уверенность снижается.

## 8. Фильтры входа

**Покупка YES:** `0.03 ≤ ask ≤ 0.25` и `p ≥ 2 × allin(ask)` и `p ≥ 0.08`.
Ноги дешевле 3¢ запрещены: переоценка дешёвых хвостов — главный подозреваемый
внешней ревизии.

**Покупка NO:** `mid ≥ 0.25` и `(mid − p) ≥ 0.15`.

Для обоих: объём рынка, распознанный бакет, непустая книга, пройденный
контракт резолюции и подтверждённые торговые параметры. Все сравнения — по
ПОЛНОЙ цене с комиссией этого рынка.

## 9. Шкала уверенности (1–5)

```
база 3
+1  если сигнал устойчив к сдвигу поправки на ±SE
+1  если все семейства моделей согласны   /  −1 если одно резко против
−1  если спред шире 8 центов
−1  если калибровка своего горизонта на менее чем 3 днях
−1  если объём рынка меньше $30 000
−1  если горизонт 2 дня и больше
тир СВОЕГО горизонта = C → потолок 2
```

Торгуем только 4 и 5. Тройки — наблюдение.

## 10. Шанс-комбо

Набор из 2–4 взаимоисключающих бакетов одного рынка. Цена набора — сумма
ПОЛНЫХ цен ног (`allin` по параметрам этого рынка). Кандидаты сортируются по
`p / allin(ask)`, добавляются по одному, шаг фиксируется при `P ≥ 0.40` и
`EV ≥ +0.15`, общая цена набора не выше 0.90.

Ограничение подхода: жадный набор не оптимален, честнее решать задачу
максимизации EV при бюджетном ограничении. См. OPEN_QUESTIONS №6.

## 11. Бюджет: один котёл на дату резолюции

Потолок $5 на погоду — это потолок **на дату погоды**, а не на UTC-день сделки
и не на каждую рекомендацию отдельно. `BudgetAllocator`:

* ключ — дата из слага рынка (`weather_date_of_slug`); неизвестная дата
  получает 0 (fail-closed);
* в остаток уже включено **потраченное по реальным позициям** этой даты
  (`portfolio_scan` группирует активность по дате погоды);
* максимумы, минимумы и серия берут деньги из ОДНОГО котла: одобренная
  рекомендация сразу резервирует сумму, следующая видит уменьшенный остаток;
* сверх этого действует общий дневной лимит `DAY_LIMIT`: даже если у даты
  остаток есть, выдаётся не больше, чем осталось на день;
* выдача меньше минимального ордера рынка не выдаётся вовсе.

Итоговая раскладка (сколько занято, кем, что осталось) печатается в отчёте в
поле `budget`, вместе со списком отклонённых кандидатов и причинами.

## 12. Размер ставки и исполнимые лоты

Четверть Келли по осторожной вероятности:

```
p_use = (p_базовая + p_стрессовая) / 2
b     = (1 − cost) / cost          cost — ПОЛНАЯ цена с комиссией
f     = p_use − (1 − p_use)/b
ставка = банкролл × f × 0.25
```

Дальше потолки: реальная глубина стакана, остаток бюджета даты, дневной лимит.
Меньше $0.50 — ставки нет.

Ставка в долларах бесполезна, если её нельзя исполнить. `combo_lots` считает
исполнимые лоты **в десятичной арифметике** (`Decimal`), и порядок жёсткий:

1. по каждой ноге — МИНИМАЛЬНЫЙ исполнимый лот по правилам рынка (минимальный
   ордер, минимальное число акций, обход книги, комиссии);
2. тонкие ноги (средняя цена дороже 1.5× лучшего аска) выбрасываются;
3. меньше двух исполнимых ног — NO BET;
4. сумма минимальных лотов больше запрошенной ставки или больше остатка
   бюджета — NO BET (никакого «добьём как получится»);
5. и только потом добор до целевого числа акций внутри потолка
   `min(ставка, остаток бюджета)`.

`exec.total_usd` не превышает ни ставку, ни остаток бюджета — это инвариант,
закреплённый тестами. Деньги считаются с допуском в один «двоичный волосок»:
нога ровно на $1.00 обязана пройти, а `0.9999999999999999` не имеет права её
отбраковать.

Реальный пример отсева: бакет 29°C в Чэнду, аск 0.5¢, объёма на уровне — на
$0.20; чтобы набрать минимум, пришлось бы платить в среднем 0.8¢, на 60%
дороже. Нога выброшена.

## 13. Вердикт

BET для комбо разрешён **только после расчёта исполнимых лотов**
(`approve_combo`):

* лоты рассчитаны (нет расчёта — нет ставки);
* исполнимых ног не меньше двух;
* EV ПОСЛЕ комиссий и лотов ≥ +0.10;
* `exec.total_usd` ≤ остатка общего бюджета даты и ≤ запрошенной ставки.

Кандидаты обходятся ОДНИМ проходом (`plan_weather`) в детерминированном
порядке; ограничения «проверяем только первые шесть» нет: каждый кандидат либо
одобрен, либо явно отклонён с причиной, и причины печатаются в отчёте.

Приоритет вердикта дня:

```
1. ИСПОЛНИМАЯ связка (полные цены с комиссиями + объём книг + минимальный ордер)
2. серия-комбо из числа ОДОБРЕННЫХ по исполнимой экономике
3. одиночная 5/5 и устойчивая
4. пропуск
```

Пропуск — нормальный и частый ответ.

## 14. Арбитраж

«Сумма асков ниже $1» **не является** арбитражем и больше нигде так не
называется. `check_arb_legs` засчитывает связку только если:

* полные цены всех ног (с комиссией ЭТОГО рынка) в сумме меньше $1;
* в книгах есть объём: число исполнимых комплектов считается по верхним
  уровням стаканов;
* на каждой ноге набирается минимальный ордер рынка.

Иначе выводится явное «не арбитраж» с причиной. Это же правило действует в
веб-скринерах.

## 15. Контур №2: землетрясения

Рынки «сколько землетрясений M6.5+ за неделю». Модель — пуассоновский процесс:
базовая интенсивность = число событий за 365 дней / 365; на остаток окна
λ = интенсивность × оставшиеся дни; вероятность бакета — сумма пуассоновских
весов поверх уже случившихся событий. Стресс: λ × 0.7 и λ × 1.4.

Отдельно отслеживаются «пограничные» события (магнитуда в пределах 0.1 от
порога): USGS пересматривает магнитуды задним числом — это реальный риск
резолюции.

Комиссии и минимальные ордера берутся из параметров этих рынков, а не из
погодной константы. Практическая находка: ликвидные рынки землетрясений
запрайсены честно.

## 16. Контур №3: крипта

Рынки «BTC/ETH above $K на дату». Эталон — риск-нейтральная вероятность из
опционов Deribit: поверхность IV, интерполяция по страйку, интерполяция полной
дисперсии по времени до резолюции, дальше N(d2). Стресс: IV × 0.9 и × 1.1.

Связка на монотонности страйков (YES по K1 + NO по K2 при K2 > K1) считается
по полным ценам с комиссиями этого рынка и проверяется по книгам через
`check_arb_legs` — без исполнимости она в отчёт не попадает.

Практическая находка: ликвидные крипторынки сведены с опционами с точностью
1–3 п.п. Контур — ловец редких разрывов, не источник дохода.

## 17. Что здесь описано исторически (в коде этого больше нет)

Прямо перечислено, чтобы старые формулы не всплывали как «действующие»:

1. **Historical Forecast API как источник калибровки.** Заменён на Previous
   Runs API (`previous_day1` / `previous_day2`): нужен прогноз, каким он был на
   конкретный горизонт, а не архив одной модели.
2. **Одна общая поправка станции на все семейства.** Заменена на поправку
   каждого семейства.
3. **Одна поправка на все горизонты.** Заменена на lead-matched калибровку и
   отдельный тир на каждый горизонт.
4. **σ = 0.6 + 0.15 × lead.** Подгонянная константа заменена на
   `τ_f² = max(0.36, std_f² − spread2_f)`; вариант `0.6 + 0.15·lead` остался
   только как запасной для семейства без калибровки.
5. **Стресс «сдвиг поправки на ±std».** Заменён на сдвиг на ±SE среднего:
   стрессуется неопределённость поправки, а не разброс погоды.
6. **Комиссия как константа проекта 0.05·p·(1−p) для всех контуров.** Заменена
   на параметры конкретного рынка.
7. **«Чистый арбитраж = сумма асков < $0.99».** Заменён на исполнимую связку с
   комиссиями и книгами.

## 18. Известные слабые места (действующие)

1. **Калибровка на 10 днях.** Очень короткое окно, сезонность в него не
   помещается; зато ловит текущий режим.
2. **Семейства моделей не взвешены** — равный вес каждому.
3. **Корреляция между городами не моделируется.** Две ставки в один день
   считаются независимыми, хотя обе зависят от качества прогноза в этот день.
4. **λ = 0.25 выбрана консервативно, а не выведена** из данных: резолюций пока
   единицы.
5. **Жадный набор комбо не оптимален** (см. OPEN_QUESTIONS №6).
6. **Мало данных.** Первая же резолюция (Мюнхен, 2 августа) была промахом:
   модель давала 32°C вероятность 35–40%, факт 30°C.
7. **Формат полей Polymarket по комиссиям и минимальным ордерам** взят из
   документации и наблюдений; из этого репозитория он офлайн не проверяется.
   Именно поэтому нераспознанные параметры дают NO BET.

## 19. Бумажная оценка полной модели

`wx_daily.py` пишет в `paper_forecasts` не только выбранные ставки, а **все
полные city-day распределения**, которые прошли контракт резолюции и проверку
полноты бакетов. Для каждого бакета до наступления исхода фиксируются:

* `p_model` — независимая вероятность ансамбля;
* `p_shrunk` — действующая вероятность после лог-пула;
* `p_market` — нормированные midpoint рынка;
* дата/горизонт, станция, тир и отпечаток правил резолюции.

`src/paper_eval.py capture` валидирует суммы вероятностей и непрерывное покрытие
от нижнего до верхнего хвоста, присваивает содержимому SHA-256 и атомарно
добавляет запись в JSONL. Повтор того же снимка идемпотентен; другая версия для
того же `event_slug + captured_at` считается конфликтом и не перезаписывает
историю.

После финальной резолюции `score` считает по одной единице city-day:

```
log-loss = −ln(p фактического бакета)
RPS = Σ(CDF_k − O_k)² / (K−1)
```

Обе метрики считаются отдельно для модели, усаженной модели и рынка. Также
собирается результат по всем дешёвым рыночным хвостам (по умолчанию ≤5¢), а
вес модели `lambda` оценивается на фиксированной сетке 0…1. Эта оценка не
меняет торговый код автоматически: малой выборке запрещено ретюнинговать
параметр без отдельного решения.

## 20. Проверяемость

* `python -m unittest discover -s tests -t .` — весь набор тестов, сеть не
  используется: все внешние API подменяются инъекцией `fetch`.

  и pull request.
