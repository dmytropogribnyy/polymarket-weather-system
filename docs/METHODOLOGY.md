# Методология

Документ описывает, как система превращает метеорологические данные в
конкретную ставку с конкретным размером. Всё, что здесь написано, реализовано
в `src/wx_daily.py`; HTML-скринеры повторяют ту же математику на JavaScript.

## 1. Источники данных

| Что | Откуда | Зачем |
|---|---|---|
| Ансамблевый прогноз | Open-Meteo Ensemble API, модели `ecmwf_ifs025`, `gfs025`, `icon_seamless`, `gem_global` | 143 члена ансамбля, почасовая температура |
| Архив прогнозов | Open-Meteo Historical-Forecast API, модель `ecmwf_ifs025` | прогноз, который был выпущен на прошедшие дни — для калибровки |
| Факт по станции | aviationweather.gov METAR, окно 336 часов | что станция реально намерила |
| Рынки | Polymarket Gamma API (`events?slug=`), CLOB (`book?token_id=`) | цены, бакеты, стаканы |
| Землетрясения | USGS FDSN `count` и `query` | базовая интенсивность и текущий счёт |
| Крипта | Deribit `get_book_summary_by_currency` | подразумеваемая волатильность опционов |

Ключевое требование к слагам Polymarket:
`highest-temperature-in-{city}-on-{month}-{day}-{year}`, для ночных минимумов
префикс `lowest`.

## 2. Определение станции резолюции

Станция берётся не «по городу», а из описания конкретного рынка. Примеры
реальных расхождений, которые это ловит:

* Шанхай резолвится по Пудуну (ZSPD), а не по центру — летом разница до 2°C.
* Москва резолвится по Внуково (UUWW).
* Сан-Франциско — по аэропорту SFO, где океанский бриз держит температуру
  сильно ниже, чем в городе.

Толпа обычно смотрит прогноз «города» из телефона. Это и есть источник
систематического расхождения, на котором живёт система.

## 3. Калибровка станции

```
для каждого из последних 10 дней:
    модельный максимум  = max по часам архивного прогноза ECMWF для этого дня
    фактический максимум = max по METAR этого дня (в местном времени станции)
    разница = факт − модель

bias = среднее разниц
std  = стандартное отклонение разниц
```

Отсечка: сегодняшний день учитывается только после 19:00 местного времени
(иначе дневной максимум ещё не наступил).

Тиры доверия:

| Тир | Условие | Следствие |
|---|---|---|
| A | n ≥ 6, std ≤ 0.8, \|bias\| ≤ 4 | полное доверие |
| B | n ≥ 4, std ≤ 1.5, \|bias\| ≤ 4 | полное доверие |
| C | всё остальное | уверенность режется до 2/5, торговать нельзя |

Пример: у Лос-Анджелеса (KLAX) bias вышел −6.55°C — это не поправка,
а признак того, что рынок резолвится по другой точке. Город исключён.

## 4. Вероятность бакета

```
для каждого члена ансамбля x:
    xc = x + bias
    p_член = Φ((hi − xc)/σ) − Φ((lo − xc)/σ)
p = среднее по членам
```

где `[lo, hi]` — границы бакета, расширенные на ±0.5 градуса
(бакет «31°C» на самом деле означает интервал [30.5, 31.5)), а

```
σ = 0.6 + 0.15 × lead    (lead — на сколько дней вперёд, в днях)
```

Для рынков в Фаренгейтах границы конвертируются в Цельсий, потому что
ансамбль отдаёт градусы Цельсия.

Смысл σ: члены ансамбля дают разброс сценариев погоды, но внутри каждого
сценария всё равно есть ошибка представления сетки и локальных эффектов.
σ — это размазывание каждого члена. **Это самое спорное место всей модели,
см. OPEN_QUESTIONS №1.**

## 5. Устойчивость и согласие моделей

Считаем ту же вероятность ещё дважды — со сдвигом поправки на `±std`:

```
pLo = P(бакет | bias − std)
pHi = P(бакет | bias + std)
```

Сигнал считается устойчивым (`robust`), если преимущество сохраняется
в обоих стрессовых сценариях.

Отдельно вероятность считается по каждому семейству моделей (ec, gf, ic, gm).
Если одно семейство даёт почти ноль там, где остальные дают много — это флаг
риска, и уверенность снижается.

## 6. Фильтры входа

**Покупка YES** (ставка на недооценённый бакет):
```
0.02 ≤ ask ≤ 0.25   и   p ≥ 2 × ask   и   p ≥ 0.08
```
То есть покупаем только дешёвые бакеты и только если модель даёт минимум
двукратный перевес над ценой.

**Покупка NO** (ставка против переоценённого бакета):
```
mid ≥ 0.25   и   (mid − p) ≥ 0.15
```

Дополнительные условия для обоих: объём рынка ≥ $10 000, бакет распознан
парсером, книга не пустая.

## 7. Шкала уверенности (1–5)

```
база 3
+1  если сигнал устойчив к сдвигу поправки
+1  если все семейства моделей согласны   /  −1 если одно резко против
−1  если спред шире 8 центов
−1  если калибровка на менее чем 3 днях
−1  если объём рынка меньше $30 000
−1  если горизонт 2 дня и больше
тир C → потолок 2
```

Торгуем только 4 и 5. Тройки идут в наблюдение.

## 8. Шанс-комбо

Вместо одной ставки на один бакет — набор из 2–4 взаимоисключающих бакетов
одного рынка, покупаемых **одинаковым числом акций** (не равными суммами).
Платим сумму асков за $1 выплаты, выигрываем, если исход попал в любой
из набора.

Алгоритм жадный: кандидаты сортируются по отношению `p / ask` (ценность на
доллар), добавляются по одному, шаг фиксируется при `P ≥ 0.40` и `EV ≥ +0.15`,
общая цена набора не выше 0.90.

Ограничение подхода: жадный набор не оптимален, честнее решать
задачу максимизации EV при бюджетном ограничении. См. OPEN_QUESTIONS №6.

## 9. Размер ставки

Четверть Келли по осторожной вероятности:

```
p_use = (p_базовая + p_стрессовая) / 2
b     = (1 − cost) / cost
f     = p_use − (1 − p_use)/b
ставка = банкролл × f × 0.25
```

Дальше потолки, по порядку: реальная глубина стакана по цене входа,
дневной лимит, минимальный ордер биржи $1. Если получается меньше $0.50 —
ставка не делается вовсе (возвращается 0).

Смешивание базовой и стрессовой вероятности — компромисс: чистая
стрессовая обнуляла тонкие, но реальные сетапы. См. OPEN_QUESTIONS №5.

## 10. Исполнимые лоты

Ставка в долларах бесполезна, если её нельзя исполнить. `combo_lots()`
для каждой ноги обходит стакан:

* набирает `max(целевое число акций, объём на минимальные $1)`;
* считает среднюю цену по факту обхода;
* **отсеивает ногу**, если средняя цена выходит дороже 1.5× лучшего аска —
  это признак того, что книга слишком тонкая и минимум в $1 приходится
  добирать по грабительской цене.

Реальный пример отсева: бакет 29°C в Чэнду, аск 0.5¢, но объёма на этом
уровне хватало на $0.20 — чтобы набрать $1, пришлось бы платить в среднем
0.8¢, то есть на 60% дороже. Нога выброшена.

## 11. Правила исполнения

* Комбо — только лимитными ордерами по ценам из плана лотов.
* Одиночная ставка: цена ниже 10¢ **или** глубина меньше 3× размера ставки —
  лимит по аску; дороже и глубже — можно маркетом с проверкой средней цены.
* Минимальный ордер Polymarket — $1. Ордера меньше отбиваются с ошибкой
  «min size: $1» (проверено на практике).

## 12. Вердикт дня

Система обязана давать один ясный ответ на категорию, а не список из
двадцати возможностей. Приоритет:

```
1. чистый арбитраж (сумма асков всех бакетов < $0.99)
2. серия-комбо (P ≥ 0.60, EV ≥ +0.20, тир A/B, ширина диапазона ≤ 25 п.п., объём ≥ $15k)
3. одиночная 5/5 и устойчивая
4. пропуск
```

Пропуск — нормальный и частый ответ. Явное правило проекта:
не ставить лишь бы ставить.

## 13. Контур №2: землетрясения

Рынки вида «сколько землетрясений M6.5+ произойдёт за неделю». Модель —
пуассоновский процесс: базовая интенсивность берётся как число событий
за последние 365 дней, делённое на 365; на остаток окна считается
λ = интенсивность × оставшиеся дни; вероятность попасть в бакет —
сумма пуассоновских весов поверх уже случившихся событий.

Стресс-сценарии: λ × 0.7 и λ × 1.4.

Отдельно отслеживается число «пограничных» событий (магнитуда в пределах
0.1 от порога рынка) — USGS пересматривает магнитуды задним числом,
и это реальный риск резолюции.

Практическая находка: ликвидные рынки землетрясений запрайсены честно.
Преимущество появляется только в свежих тонких недельных рынках и в
арбитраже (сумма асков ниже $1).

## 14. Контур №3: крипта

Рынки «BTC/ETH above $K на дату». Эталон — риск-нейтральная вероятность
из опционов Deribit: строится поверхность подразумеваемой волатильности,
IV интерполируется по страйку, полная дисперсия интерполируется по времени
до момента резолюции рынка, дальше обычная N(d2).

Стресс: IV × 0.9 и × 1.1.

Отдельно ищется арбитраж на монотонности страйков: если YES по страйку K1
плюс NO по страйку K2 (где K2 > K1) стоят вместе меньше $1, набор гарантированно
возвращает не меньше доллара.

Практическая находка: ликвидные крипторынки уже сведены с опционами
с точностью 1–3 процентных пункта. Контур работает как ловец редких разрывов,
а не как источник постоянного дохода.

## 15. Известные слабые места

Честный список того, что в системе плохо:

1. **σ подобрана, а не выведена.** Формула `0.6 + 0.15 × lead` не имеет
   вывода, она подогнана на глаз.
2. **Поправка станции одна на все горизонты.** Ошибка прогноза на сутки
   и на двое суток имеет разную природу, а поправка используется одна.
3. **Калибровка на 10 днях.** Это очень короткое окно, сезонный эффект
   в него не помещается. Зато оно ловит текущий режим погоды.
4. **Семейства моделей не взвешены.** ECMWF, GFS, ICON и GEM дают разное
   число членов и имеют разное качество, но в общий котёл идут на равных.
5. **Корреляция между городами не моделируется вообще.** Две ставки в один
   день в разных городах считаются независимыми, хотя обе зависят от общего
   качества прогноза в этот день.
6. **Цена рынка не используется как априор.** Модель считает вероятность
   с нуля и сравнивает с ценой. Более честный байесовский подход — сдвигать
   свою оценку в сторону рынка. См. OPEN_QUESTIONS №3.
7. **Мало данных.** Резолюций пока единицы, и первая же (Мюнхен, 2 августа)
   была промахом: модель давала 32°C вероятность 35–40%, факт 30°C.
